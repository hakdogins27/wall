Design decisions & implementation handoff
  • A modern interpretation of the original Wall: quiet blue header, a clear type hierarchy (22px composer prompt, 18px feed heading, 16px post text, 14px author and 12px metadata), three purposeful desktop columns: posting identity, widest composer/feed, and notifications. Original Wall identity; no copied Facebook branding, social statistics, navigation or unrelated actions.
  • Desktop uses one top-aligned flex container capped at 1920px with 24px outer gutters: 280px identity, flexible widest feed and 270px notifications, with consistent 28px gaps and 24px panel padding. The identity uses a circular avatar beside the wrapping name; post text stays within 75 characters per line. The page heading is visually hidden to keep the composer aligned with both side panels. Below 1180px, panels stack as feed, profile and notifications, all remaining accessible. Below 820px, content becomes one column with the composer/feed first and context after it. Side margins tighten, controls remain at least 44px tall, textarea text increases to 16px on small phones and long posts wrap. Newly shared posts gently fade/slide in; reduced-motion preferences disable the animation. No forced scroll.
  • Composer: visible label; 280-character maximum; disable Share for whitespace-only content or while sending. Keep draft on failure, show a specific error, and allow retry using Share. On success clear draft, announce success, insert the confirmed post first, and return focus to composer.
  • Initial feed loading is distinct from submission. Failed loading shows Retry. Empty feed invites the first post. Production should preserve visible posts if a later refresh fails.
  • Production: persist through Supabase; order by server creation time descending with a stable tie-breaker; subscribe to new confirmed rows and deduplicate by ID. Keep composer draft during incoming updates. Do not insert an unconfirmed post. Realtime disconnection should preserve the feed and show a refresh recovery action. Add a Load older button when earlier posts exist beyond the initial page; preserve visible posts during pagination failures.
  • Use semantic controls, visible keyboard focus, high-contrast text, live submission feedback, and human-readable timestamps with machine-readable dates. Production must count Unicode code points with Array.from(text).length to match PostgreSQL char_length. The prototype uses the same code-point counter and disables posting above the limit without deleting the draft. An emoji sequence can contain multiple code points.
  • Assumption for approval: public anonymous posting, one fixed display author. Optional post photos and shared profile photo/About/Skills/Links with view-first /profile navigation and a separate public /profile/edit editor were approved after this prototype. No login, likes, comments, or search. Anyone can edit the shared profile.
  • This prototype’s state selector is for review only and is absent from the final application. No persistence or network service is connected. Implementation target after approval: React 19, Next.js, Supabase, Tailwind and shadcn/ui; Realtime and the 280-character limit are required.
